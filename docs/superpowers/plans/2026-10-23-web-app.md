# Milestone 4: Web app (FastAPI + Next.js) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wrap the existing LangGraph quiz graph in a FastAPI API that streams step events, and build the prototype's onboarding, study workspace and progress dashboard in Next.js, after cleaning up the graph and hardening the backend for a long-running server.

**Architecture:** Phase A reshapes the graph without changing behaviour (the existing tests are the safety net). Phase B adds the correctness, safety and daily-cap pieces, and extracts the session and subject logic that `cli.py` holds today into shared services (`ebb/study.py`, `ebb/subjects.py`) used by both the CLI and the API. Phase C adds `ebb/api/` (FastAPI, Server-Sent Events). Phase D adds `frontend/` (Next.js App Router, CSS Modules ported from the prototype), which calls the API directly from the browser.

**Tech Stack:** Python 3.14, LangGraph 1.2, psycopg 3, FastAPI ≥ 0.161 (built-in `fastapi.sse`), uvicorn ≥ 0.54, python-multipart; Next.js ≥ 16.4, React ≥ 19.3, TypeScript, Vitest + React Testing Library, Playwright; Postgres 18.6; Docker Compose.

**Spec:** [docs/superpowers/specs/2026-10-23-web-app-design.md](../specs/2026-10-23-web-app-design.md). Read it before any task; where this plan is silent, the spec decides.

- Graph nodes catch only named exception classes, never bare `except Exception`.
- No test calls a real model or Tavily. Backend tests: `cd backend; $env:EBB_REQUIRE_DB=1; $env:LANGGRAPH_STRICT_MSGPACK='true'; uv run pytest -q`; `uv run ruff check .`; `uv run ruff format --check .`.
- Styling: CSS Modules ported from `ebb-prototype.html`'s variables and styles. No Tailwind, no shadcn, no chart library. Fonts: Fraunces (headings), Inter (UI).
- Groq only; the Mistral fallback code stays as it is and nothing new depends on it.
- Sessions saved by milestones 2 and 3 must still resume.
- Exact copy (use verbatim):

  - `"Daily limit reached — your progress is saved. It resets at midnight."`
  - `"The tutor won't help with that topic."` / onboarding: `"The tutor won't help with these notes."`
  - `"The tutor couldn't respond — your progress is saved. Try again in a minute."` (existing)
  - `"{name} already exists — add notes to it from its Sources list."` (web) / the CLI keeps its own existing message
  - `"This upload expired — add the files again."`
  - `"Your tide chart fills in as you review — come back after 3 sessions"`
  - `"Tide's high. Next review {weekday}."`, `"Next review: {weekday} · {n} concepts"`
- Tide bands (D7 names, prototype thresholds): tide ≥ 0.80 → `"high tide"`, ≥ 0.60 → `"ebbing"`, below → `"low tide"`, stage 0 → `"new"`.
- Step labels (spec table): `retrieve_notes` "Reading your notes…", `generate_questions` "Writing questions…" / web mode "Writing questions from the web…", `verify_citations` "Checking citations against your notes…", `search_web` "Searching the web…", `grade_answer` "Grading against your notes…" / no notes "Grading…", `teach` "Writing a short lesson…", `regrade` "Re-checking…", `extend_subject` "Finding more advanced concepts…"; every other node has no label.

## Review Focus

1. **A double-click or retried request on an answer** (two `reply` calls with the same `attempt_id`, or the same dispute id) must count once and both calls must return the same turn — test in Task 19.
2. **The browser disconnecting mid-turn** (refresh while grading) must leave the session resumable; resuming finishes the cut-off step once and the answer counts once — test in Task 19.
3. **Two tabs, or a tab and `ebb study`, on one session**: the second gets the busy copy and can only start fresh; the first keeps working — tests in Tasks 13 and 19.
4. **A blank or whitespace-only short answer, or an MCQ answer outside 1–4**: the API answers 422 and the composer's Send stays disabled; nothing reaches the graph — tests in Tasks 19 and 23.
5. **The API unreachable or restarted while a page is open**: the page shows the error card with Retry instead of crashing; a restarted API loses only drafts — tests in Tasks 18 and 23.
